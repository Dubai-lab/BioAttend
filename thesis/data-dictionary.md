# DATA DICTIONARY

Section 4.6.3 of Chapter Four. Every table in the BioAttend database, with its
fields, data types, nullability and purpose.

**Notation.** PK = primary key, FK = foreign key, U = unique constraint.
`uuid` values are generated by the database. `timestamptz` stores an absolute
instant with time zone, so records remain correct across the shifts that cross
midnight.

---

## 4.6.3.1 Reference data

### Table: departments

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Department identifier |
| code | VARCHAR (U) | No | Short code, e.g. ICU, EMG |
| name | VARCHAR | No | Department name |
| is_clinical | BOOLEAN | No | True for clinical departments, false for administrative. Default true |
| created_at | TIMESTAMPTZ | No | Record creation time |

### Table: job_titles

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Job title identifier |
| title | VARCHAR (U) | No | Job title, e.g. Staff Nurse |
| category | VARCHAR | No | One of medical, nursing, allied_health, support, admin |
| created_at | TIMESTAMPTZ | No | Record creation time |

### Table: shifts

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Shift identifier |
| code | ENUM (U) | No | morning, evening or night |
| name | VARCHAR | No | Display name, e.g. Morning Shift |
| starts_at | TIME | No | Shift start time of day |
| ends_at | TIME | No | Shift end time of day |
| checkin_opens_before_min | INT | No | Minutes before start that check-in opens. Default 30 |
| checkin_grace_after_min | INT | No | Minutes after start that check-in remains open. Default 60 |
| checkout_opens_before_min | INT | No | Minutes before end that check-out opens. Default 30 |
| checkout_closes_after_min | INT | No | Minutes after end that check-out closes. Default 60 |
| crosses_midnight | BOOLEAN | No | True for the night shift. Determines whether a day is added when computing the shift end |
| is_active | BOOLEAN | No | Whether the shift is in use. Default true |
| created_at | TIMESTAMPTZ | No | Record creation time |
| updated_at | TIMESTAMPTZ | No | Last modification, maintained by trigger |

### Table: hospital_settings

Single-row table holding institution-wide configuration.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | BOOLEAN (PK) | No | Always true. Constraint restricts the table to one row |
| hospital_name | VARCHAR | No | Institution name shown in the interface |
| system_name | VARCHAR | No | System name shown in the interface |
| timezone | VARCHAR | No | IANA time zone. Attendance dates and shift windows are computed in this zone |
| face_match_threshold | REAL | No | Minimum cosine similarity to accept a face match |
| face_match_margin | REAL | No | Minimum lead the best match must hold over the runner-up |
| fingerprint_min_quality | INT | No | Minimum template quality accepted at enrolment |
| min_shift_duration_min | INT | No | Minimum elapsed time before a scan may be read as a check-out |
| updated_at | TIMESTAMPTZ | No | Last modification |

## 4.6.3.2 People

### Table: staff

The people whose attendance is recorded. Deliberately **not** linked to any
authentication table — staff have no accounts and cannot sign in.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Staff identifier |
| staff_no | VARCHAR (U) | No | Hospital staff number, e.g. NGH-1002 |
| full_name | VARCHAR | No | Staff member's full name |
| department_id | UUID (FK) | No | References departments.id |
| job_title_id | UUID (FK) | No | References job_titles.id |
| phone | VARCHAR | Yes | Contact number |
| email | VARCHAR | Yes | Contact email. Not a login |
| status | ENUM | No | active, suspended or terminated. Default active |
| starts_on | DATE | No | Employment start date |
| ends_on | DATE | Yes | Employment end date, set when terminated |
| consent_given | BOOLEAN | No | Whether biometric consent has been recorded. Default false |
| consent_given_at | TIMESTAMPTZ | Yes | When consent was recorded. Constrained to be present whenever consent_given is true |
| consent_form_url | VARCHAR | Yes | Reference to the signed consent form |
| fingerprints_enrolled | INT | No | Count of stored templates, maintained by trigger |
| face_enrolled | BOOLEAN | No | Whether any face embedding exists, maintained by trigger |
| created_at | TIMESTAMPTZ | No | Record creation time |
| updated_at | TIMESTAMPTZ | No | Last modification, maintained by trigger |

### Table: profiles

Console users — administrators and supervisors. One row per authentication
account.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK, FK) | No | References the authentication user identifier |
| full_name | VARCHAR | No | User's full name |
| email | VARCHAR | No | Sign-in email address |
| role | ENUM | No | admin or supervisor. Default supervisor |
| department_id | UUID (FK) | Yes | Department a supervisor oversees. Null for administrators, who see all departments |
| is_active | BOOLEAN | No | Whether the account may sign in. Default true |
| created_at | TIMESTAMPTZ | No | Record creation time |
| updated_at | TIMESTAMPTZ | No | Last modification, maintained by trigger |

## 4.6.3.3 Biometric data

### Table: fingerprint_templates

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Template identifier |
| staff_id | UUID (FK) | No | References staff.id. Deleting a staff member deletes their templates |
| finger | ENUM | No | left_thumb, left_index, right_thumb or right_index |
| template | TEXT | No | Base64 encoding of the 512-byte proprietary template. Cannot be reversed into a fingerprint image |
| quality | INT | No | Capture quality, 0–100. Constrained to that range |
| minutiae | INT | Yes | Minutiae count, where reported by the device |
| enrolled_by | UUID (FK) | Yes | References profiles.id — the administrator who captured it |
| device_id | VARCHAR | Yes | Reader that performed the capture |
| created_at | TIMESTAMPTZ | No | Capture time |

Unique constraint on (staff_id, finger) — one template per finger per person,
so re-capturing a finger replaces it rather than accumulating duplicates.

### Table: face_embeddings

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Embedding identifier |
| staff_id | UUID (FK) | No | References staff.id |
| embedding | VECTOR(512) | No | L2-normalised ArcFace descriptor. Cannot be reversed into a photograph |
| angle | VARCHAR | No | front, left, right, up or down |
| quality | REAL | No | Detector confidence at capture time |
| enrolled_by | UUID (FK) | Yes | References profiles.id |
| created_at | TIMESTAMPTZ | No | Capture time |

Unique constraint on (staff_id, angle). Indexed with IVFFlat using cosine
distance, so similarity search is performed by the database rather than the
client — necessary because the check-in station is not permitted to read
biometric records.

## 4.6.3.4 Devices

### Table: readers

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | VARCHAR (PK) | No | Reader identifier, e.g. HR-DESK-01 |
| label | VARCHAR | No | Human-readable name |
| location | VARCHAR | Yes | Physical location |
| firmware | VARCHAR | Yes | Firmware version reported by the device |
| resolution_dpi | INT | Yes | Sensor resolution |
| capacity | INT | No | Template slots available in device flash. Default 1000 |
| last_synced_at | TIMESTAMPTZ | Yes | When templates were last written to the device |
| last_seen_at | TIMESTAMPTZ | Yes | When the device last responded |
| is_active | BOOLEAN | No | Whether the reader is in service. Default true |
| created_at | TIMESTAMPTZ | No | Registration time |

### Table: reader_slots

Maps a physical storage slot in a reader to the staff member whose template
occupies it. The device returns a slot number on a match and knows nothing
about people.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| reader_id | VARCHAR (PK, FK) | No | References readers.id |
| slot_id | INT (PK) | No | Slot number in device flash. Constrained to be non-negative |
| template_id | UUID (FK) | No | References fingerprint_templates.id |
| staff_id | UUID (FK) | No | References staff.id |
| synced_at | TIMESTAMPTZ | No | When this slot was written |

Composite primary key (reader_id, slot_id), with a unique constraint on
(reader_id, template_id).

### Table: kiosks

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Station identifier |
| code | VARCHAR (U) | No | Station code, e.g. KIOSK-MAIN-01 |
| label | VARCHAR | No | Human-readable name |
| location | VARCHAR | Yes | Physical location |
| token_hash | VARCHAR | No | Bcrypt hash of the station credential. The plaintext is displayed once at registration and never stored |
| reader_id | VARCHAR (FK) | Yes | References readers.id |
| has_camera | BOOLEAN | No | Whether a camera is attached. Default true |
| is_active | BOOLEAN | No | Whether the station may record attendance. Default true |
| last_seen_at | TIMESTAMPTZ | Yes | When the station last submitted a request |
| created_at | TIMESTAMPTZ | No | Registration time |

## 4.6.3.5 Operational data

### Table: shift_assignments

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Assignment identifier |
| staff_id | UUID (FK) | No | References staff.id |
| shift_id | UUID (FK) | No | References shifts.id |
| shift_date | DATE | No | Date the shift **begins**. A night shift starting 23:00 on the 7th carries shift_date 7 even though it ends on the 8th |
| notes | TEXT | Yes | Free-text note from the supervisor |
| created_by | UUID (FK) | Yes | References profiles.id |
| created_at | TIMESTAMPTZ | No | Record creation time |

Unique constraint on (staff_id, shift_date) — one shift per person per day,
enforced by the database rather than by the interface.

### Table: attendance

One row per staff member per shift date. Check-in and check-out are columns on
that row rather than separate events, so "already checked in today" is a
property of the schema rather than a query result.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Attendance record identifier |
| staff_id | UUID (FK) | No | References staff.id |
| shift_date | DATE | No | Date the shift began, not the calendar date of the scan |
| shift_id | UUID (FK) | Yes | References shifts.id. Null when the attendance was unscheduled |
| department_id | UUID (FK) | No | Denormalised from staff, so department-scoped access control does not require a join on every row |
| check_in_at | TIMESTAMPTZ | Yes | Arrival time as captured |
| check_in_method | ENUM | Yes | fingerprint, face or manual |
| check_in_confidence | INT | Yes | Match score at check-in. Retained as evaluation data |
| check_in_status | ENUM | Yes | on_time, late, late_unapproved or unscheduled |
| check_in_kiosk_id | UUID (FK) | Yes | References kiosks.id — which station recorded it |
| check_out_at | TIMESTAMPTZ | Yes | Departure time as captured |
| check_out_method | ENUM | Yes | fingerprint, face or manual |
| check_out_confidence | INT | Yes | Match score at check-out |
| check_out_status | ENUM | Yes | on_time, early, late or missing |
| check_out_kiosk_id | UUID (FK) | Yes | References kiosks.id |
| requires_approval | BOOLEAN | No | True where the record needs supervisor sign-off. Default false |
| approved_by | UUID (FK) | Yes | References profiles.id — who approved it |
| approved_at | TIMESTAMPTZ | Yes | When it was approved |
| approval_note | TEXT | Yes | Supervisor's note. Approval never alters the captured times |
| created_at | TIMESTAMPTZ | No | Record creation time |
| updated_at | TIMESTAMPTZ | No | Last modification, maintained by trigger |

Unique constraint on (staff_id, shift_date). A check constraint requires
check_out_at to be later than check_in_at where both are present.

### Table: attendance_attempts

Every recognition attempt, including those refused. This is the only place a
refused scan is recorded, and therefore the only source from which a false
rejection rate can be computed.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Attempt identifier |
| staff_id | UUID (FK) | Yes | References staff.id. Null when the person was not identified |
| kiosk_id | UUID (FK) | Yes | References kiosks.id |
| method | ENUM | No | fingerprint, face or manual |
| confidence | INT | Yes | Match score returned by the matcher |
| decision | VARCHAR | No | check_in, check_out, rejected or duplicate |
| reason | VARCHAR | Yes | Why the decision was reached, e.g. too_early, window_closed, unscheduled |
| occurred_at | TIMESTAMPTZ | No | Time of the attempt |

### Table: audit_log

Append-only record of console actions. No update or delete policy exists for
any application role, so entries cannot be edited away after the fact.

| Field | Data Type | Nullable | Description |
|---|---|---|---|
| id | UUID (PK) | No | Entry identifier |
| actor_id | UUID (FK) | Yes | References profiles.id. Null for system actions |
| action | VARCHAR | No | e.g. staff.enrolled, face.captured, attendance.approved |
| entity | VARCHAR | No | Table or object affected |
| entity_id | VARCHAR | Yes | Identifier of the affected record |
| detail | JSONB | Yes | Additional context. Biometric payloads are redacted before writing |
| occurred_at | TIMESTAMPTZ | No | Time of the action |

## 4.6.3.6 Summary

| Group | Tables | Purpose |
|---|---|---|
| Reference | 4 | Departments, job titles, shift definitions, configuration |
| People | 2 | Staff members and console users |
| Biometrics | 2 | Fingerprint templates and face embeddings |
| Devices | 3 | Readers, slot mapping, check-in stations |
| Operational | 4 | Roster, attendance, attempts, audit |
| **Total** | **15** | |

Three conventions hold across the schema. Every table carries a `created_at`,
and those that can be modified carry an `updated_at` maintained by a trigger
rather than by the application. Foreign keys to reference data use `restrict`
on delete, so a department in use cannot be removed; foreign keys to `staff`
use `cascade`, so removing a staff member removes their biometric data with
them. No table stores a raw biometric image — only templates and embeddings,
neither of which can be reversed into the original sample.
